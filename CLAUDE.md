# Warzone TD — guide for AI coding sessions

A mazing tower defense (inspired by the Flash game *Warzone Tower Defense*) in TypeScript + Vite + PixiJS 8.
There is no road: towers are the walls and ground units path around them (they can never be fully
blocked). Live at https://rschalch.github.io/warzone-td/ — repo `rschalch/warzone-td`.

Read this file first; `README.md` is the player-facing overview.

## Commands

```sh
npm install
npm run dev        # Vite dev server (http://localhost:5173)
npm run build      # tsc --noEmit + production build into dist/
npm run smoke      # end-to-end test in headless Chrome: menus, building, waves, replay + save determinism
npm run gauntlet   # balance probe: damage per dollar of every tower at levels 1/5/10 vs a standard wave
npm run bot        # a heuristic bot plays whole games (env: MAPS=0,1 DIFF=easy,normal VERBOSE=1); slow (minutes)
```

- **Before finishing any change: `npx tsc --noEmit`, `npm run build`, and `npm run smoke` must all pass.**
  The smoke test needs Google Chrome installed (it drives it through `playwright-core`, channel `chrome`).
- **Deploying:** pushing to `main` runs `.github/workflows/pages.yml`, which builds and publishes to GitHub
  Pages (~30 s). Check with `gh run list --limit 1`. The user expects finished work to be committed and pushed.
  Commit messages end with a `Co-Authored-By:` line for the model.
- `vite.config.ts` uses `base: './'` so the build works under the Pages sub-path. Don't change it.

## Ground rules (things that break if ignored)

1. **The simulation is deterministic.** Replays, co-op lockstep and saved games all rely on it.
   - Gameplay randomness only from `sim.rng`. Cosmetic randomness (particles) only from `sim.vr`.
     Never use `Math.random()`, `Date` or `performance.now()` inside `src/game/`.
   - **Never mutate simulation state from the UI.** Every player action is a `Command`
     (`src/game/commands.ts`) applied by `Sim.exec()` between ticks, issued through `session.issue()`.
     A new player action = a new `Command` variant + a `case` in `Sim.exec`.
   - Visual/UI-only data the sim produces (events, `waveDamage`) must never be read back by gameplay code.
   - New sim state is saved automatically if it is a typed array or a number/boolean/string field on `Sim`.
     Fields holding **object references** (e.g. a `Tower`) must be mapped to ids in `Sim.snapshot()` and
     back in `Sim.restore()`. `npm run smoke` checks replay + restore equivalence by state hash.
2. **Map size is a live module binding.** `COLS`, `ROWS`, `MAP_W`, `MAP_H` in `src/game/defs.ts` change per
   map (`setMapSize`). Always construct the sim with `Sim.create(config)` (it builds the map before any
   grid-sized arrays exist). Code that builds another map temporarily (menu previews) must restore the size.
3. **`src/game/` is DOM-free** (no `document`, no Pixi). The balance scripts run it in Node.
4. **One texture atlas.** Pixi `ParticleContainer`s need every sprite on a single texture source; the
   atlas is limited to 4096 logical px tall (8192 px at `RES` 2). Models are baked at startup in Web Workers
   (`src/render/bake.ts`, `bake.worker.ts`) — `models.ts`/`bake.ts` must stay DOM-free (OffscreenCanvas only).
   Startup is ~0.56 s; measure it after adding models. Tower bases are shared by all towers (`basel{level}`)
   with each tower's colour drawn as a tinted overlay (`basecorners`) — don't bake per-tower×per-level models.
5. **Two cameras.** Everything is projected through `Projection` (`src/render/projection.ts`): `top`
   (default) and `iso`. Upright things are drawn at `p.x(x,y), p.y(x,y) - z * p.lift`; things lying on the
   ground go in the renderer's ground container (world coordinates through `groundMatrix`). Test both (`V`).
6. **Performance matters to the user.** Sim data is struct-of-arrays typed arrays with no per-frame
   allocation in hot loops; spatial hash for range queries; renderer culls off-screen sprites. The stress
   test button (footer) must stay at 60 fps.

## Architecture

| Path | What it is |
|---|---|
| `src/game/defs.ts` | Static data: enemies, the 34 towers (level-1 stats; levels 2-10 are generated by `grow()`), combos, waves, economy constants |
| `src/game/sim.ts` | The whole simulation: fixed 60 Hz `step()`, enemies/projectiles/fx as typed arrays, towers, zones, drones, hero, items, auras, `exec(cmd)`, `snapshot()/restore()`, `stateHash()`, events |
| `src/game/commands.ts` | The `Command` union |
| `src/game/config.ts` | `GameConfig` (map, difficulty, modifiers, perks, seed), difficulties, challenge modifiers, research perks |
| `src/game/maps.ts`, `mapgen.ts` | Campaign maps, `buildMap()`: cell types `T_BUILD/T_ROCK/T_GATE/T_WATER/T_MOUNT`, rivers, mountain ranges, rocks (obstacles never cut a route), editor paint (RLE); seeded random maps, daily challenge |
| `src/game/partner.ts` | The AI partner (Co-op with AI): reads the sim, returns `Command`s (`place` with `by: PARTNER`); run by `Session` every `PARTNER_EVERY` ticks in local games |
| `src/game/flow.ts`, `spatial.ts`, `rng.ts` | Dijkstra flow fields per route, counting-sort spatial hash, mulberry32 RNG |
| `src/app/session.ts` | A running game: sim + command log; local / replay / co-op lockstep (input delay 6 ticks, state-hash desync checks) |
| `src/app/net.ts` | Co-op over WebRTC via PeerJS (public broker only for the introduction; room codes) |
| `src/app/share.ts` | Replay / custom-map links (deflated JSON in the URL hash) |
| `src/app/storage.ts`, `settings.ts`, `profile.ts` | localStorage/IndexedDB, player settings, medals/perks/leaderboard/custom maps |
| `src/audio/sound.ts` | Playback (panning, distance, convolution reverb, limiter) and the live orchestral score: six pieces played in turn (`TRACKS`), strings/brass/choir over taikos, layered by `intensity` |
| `src/audio/dsp.ts`, `sfx.worker.ts` | Offline synthesis of every effect into sample banks (a few variations each), rendered in a worker ~1.5 s after boot. No audio files |
| `src/render/models.ts` | Every 3D model as stacked top-down parts (sprite stacking) |
| `src/render/bake.ts`, `bake.worker.ts`, `atlas.ts` | Baking models (16 iso headings + 1 top-down frame), effect textures, decals, terrain markings, atlas packing, tower icons |
| `src/render/landscape.ts`, `landscape.worker.ts`, `terrainGL.ts` | Terrain: eroded heightfield + fields, built in a worker; WebGL2 cartoon ground shader |
| `src/render/renderer.ts` | Draws a sim each frame: depth-sorted sprites, projectiles, effects, beams, overlays, wrecks, floating text |
| `src/ui/hud.ts` | DOM HUD: build palette (all towers at once), side info panel, tactical bar, wave preview, reports |
| `src/ui/codex.ts` | The long "how it works" texts for towers, enemies, items, abilities |
| `src/ui/menus.ts`, `editor.ts`, `minimap.ts` | Menu screens, map editor, minimap |
| `src/main.ts` | Boot, camera (pan/zoom/shake), input (mouse, keys, touch), event → sound/effects dispatch, game lifecycle, saves |
| `scripts/` | `smoke.mjs` (browser test), `gauntlet.ts` + `bot.ts` (balance; built with `vite build --ssr`) |
| `public/` | PWA manifest, icon, service worker (offline play; bump `CACHE` when cached files change) |

Data flow per frame: `main.frame()` → `session.advance(dt)` (runs due commands, then `sim.step()` per tick) →
`handleEvents()` (sound, shake, renderer marks) → `view.render(alpha, overlayState)` → `hud.update()`.

## How to…

**Add a tower:** add an entry to `TOWERS` in `defs.ts` (add its `kind` to `TowerKind`) with only its level-1
stats in `levels: [{...}]`; `grow()` generates levels 2-10 (mark `single: true` for a tower with no upgrades).
Implement its behaviour as a `case` in `Sim.updateTower()` (passive/aura towers: in
`refreshAuras()`). Add a turret model `t_<kind>` in `models.ts`, a description in `codex.ts` (`TOWER_HELP`), and a
sound: a recipe in `RECIPES` (`dsp.ts`) named after the kind plus `GAIN`/`THROTTLE` entries in `sound.ts` (the `EV_SHOT` event plays the sound named after the kind). Then run `npm run gauntlet`
and keep its level-1 value per dollar roughly within 0.5–1.1 of the Gun.

**Add an enemy:** `ENEMIES` + an `EN_*` constant in `defs.ts`, a model (`tex` name) in `models.ts`, an entry in
`ENEMY_HELP` (`codex.ts`, same index), a wave rule in `buildWave()`, and optionally a `THREAT_TIPS` line in `hud.ts`.

**Add a player action:** `Command` variant → `Sim.exec` case → UI calls `issue({...})` in `main.ts`.

**AI partner:** `Partner.think(sim)` must stay read-only and cheap. Placement checks (`placeStatus`) run a path
search per route (~1.5 ms each on the biggest map), so a placement is spread over several thinks (`Plan`); keep
every think under ~10 ms. Its commands are logged, so replays never run it. Measure changes with
`SOLO=1 SEEDS=4 npm run bot` (partner alone) and `PARTNER=0.5 npm run bot` (alongside the bot).

**Debug in the browser:** `window.game` exposes `sim`, `session`, `app`, `camera`, `look(x, y, zoom)`,
`quick(mapIndex, difficulty)` (start a game instantly), and the `Session`/`Sim` classes. Headless checks are
easiest with a small `playwright-core` script like `scripts/smoke.mjs`; take screenshots to verify visuals.

## What the user cares about (decisions already made)

- It must be a **mazing** TD (no predefined path) like the original; large maps with pan/zoom and a minimap.
- **Top-down camera is the default**; isometric is an option (`V`), remembered between sessions.
- **All 34 towers visible at once** in the build palette, with icons — no tabs or submenus.
- Clicking a tower on the battlefield **selects it even while a build tool is active**.
- The side panel **explains** whatever is clicked or hovered (towers, enemies, commander, items, abilities).
- **10 upgrade levels** per tower; every level raises damage, range and fire rate and **looks different**.
- Detailed models, performance, and polish (sound, effects) are all valued. Verify visual changes with screenshots.

**Terrain:** `MapDef.rivers` / `mountains` / `forests` (generated) or `paint` (editor). Water is walkable at
`WATER_SLOW` speed (`Sim.groundSlow`, folded into `tarGrid`) and costs `1 / WATER_SLOW` in the flow fields;
mountains (`T_MOUNT`) and forests (`T_TREE`) are `blocked`. None is buildable (`footprint` needs `T_BUILD`). The look
(all cosmetic, never read by the sim): `render/landscape.ts` builds a heightfield (hills, a ridged spine over every
massif, river valleys) carved by droplet hydraulic erosion, plus moisture, forest mask, cast shadows and AO;
`render/terrainGL.ts` paints it in one WebGL2 shader in a cartoon (Kingdom Rush-like) style; `scenery()` in
`atlas.ts` puts cartoon trees/bushes (`tree*`, `pine*`, `bush*` models) only on blocked cells (forests, mountains),
so they never hide a tower spot. The game starts with a coarse landscape (`buildBackground`, sub=1) and
`refineBackground()` swaps in the detailed one built in `landscape.worker.ts`. Height inputs must be smooth to
their slope (multi-pass blurs, no hard `max`), or the light draws crease lines. Without WebGL2: `flatGround()`. Adding fields to a campaign
`MapDef` changes that map for new games only: saves and replays carry their own copy of the def.

## WW2 mode (branch `ww2`, never merged to `main`: main deploys publicly)

Design and phase plan: `docs/ww2-design.md`. `GameConfig.ww2 = { side, foe }` selects it; `Sim.create()` calls
`setRuleset()` (`src/game/rules.ts`), which swaps the live bindings `TOWERS`, `ENEMIES`, `COMBOS`, `CATEGORIES`,
`RANKS`, `buildWave` and the `WW2` flag in `defs.ts` (like the map size). Never call it while another game is
running; menus use `rulesetFor(cfg.ww2)` to read a ruleset without installing it.
- Data: `src/game/ww2.ts` (German emplacements, Soviet attackers, waves). A `TowerDef` has a unique `kind` and a
  `role` (the behaviour in `Sim.updateTower`; `Tower.kind` holds the role). WW2 roles beyond the classic ones:
  `at` (armour-piercing direct fire; flak bursts against aircraft), `wire` (slows infantry only), `stuka`.
- Ballistics: `Sim.ballistics()` — `pen` (mm, falls off with range) against `arm` [front, side, rear, top] by the
  shooter's bearing to the hull heading; blasts and bombs hit the top. Bounce = ~0 damage; overmatch may crit.
  `canHurt()` keeps crews from targeting armour they can't penetrate. Infantry get suppression (`eSupp`).
- Models: `src/render/models_ww2.ts` (set `ww2`), baked lazily the first time a WW2 game starts
  (`buildAtlas(['classic','ww2'])` in `startGame`), so the boot stays as fast as before.
- Return fire: attackers with an `EnemyDef.gun` pick a defender (`pickDefender`: towers with `hp`, or the
  commander as id -1; `eTgt`), tanks halt to aim (`eAimT`), and `hitDefender()` applies pen against the
  emplacement's `fort` (mm, rises with level like the base visuals). Small arms mostly suppress crews
  (`Tower.supp` slows their fire). At 0 HP a tower becomes rubble (`wreck`: walkable, slow, rebuilt with the
  `repair` command); the Workshop role heals towers in range. Katyusha salvos are typed arrays (`rk*`).
- Balance: `WW2=1 npm run bot`. The AI partner is off in WW2 for now.

## Balance notes

The economy and tower values were tuned with `npm run gauntlet` and `npm run bot`. Last bot results: it wins
every map on Easy and the single-route maps on Normal, loses multi-route maps on Normal and most maps on Hard.
The bot only builds along the natural path (no real mazing), so humans do much better. Multi-route maps pay more
(`routeFactor` in `Sim`). Stealth units are revealed by radar or spotted point-blank (`STEALTH_DETECT`).

## Known limitations

- Leaderboard is local to the browser (an online one needs a backend).
- Co-op has no TURN relay: very strict NATs can fail to connect.
- Saves happen at each wave start and when the tab is hidden; continuing resumes from the last save.
