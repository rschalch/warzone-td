# Warzone TD — guide for AI coding sessions

A mazing tower defense (inspired by the Flash game *Warzone Tower Defense*) in TypeScript + Vite + PixiJS 8.
There is no road: towers are the walls and ground units path around them (they can never be fully
blocked). Live at https://rschalch.github.io/warzone-td/ — repo `rschalch/warzone-td`.

Read this file first; `README.md` is the player-facing overview.

## Commands

```sh
npm install
npm run dev        # Vite dev server (http://localhost:5173)
npm run build      # tsc --noEmit + production build into dist/
npm run smoke      # end-to-end test in headless Chrome: menus, building, waves, replay + save determinism
npm run gauntlet   # balance probe: damage per dollar of every tower at levels 1/5/10 vs a standard wave
npm run probe      # every weapon vs a target at 50/80/95/100% of its range (WW2=1 ALL=1 for every matchup)
npm run bot        # a heuristic bot plays whole games (env: MAPS=0,1 DIFF=easy,normal VERBOSE=1); slow (minutes)
```

- **Before finishing any change: `npx tsc --noEmit`, `npm run build`, and `npm run smoke` must all pass.**
  The smoke test needs Google Chrome installed (it drives it through `playwright-core`, channel `chrome`).
- **Deploying:** pushing to `main` runs `.github/workflows/pages.yml`, which builds and publishes to GitHub
  Pages (~30 s). Check with `gh run list --limit 1`. The user expects finished work to be committed and pushed.
  Commit messages end with a `Co-Authored-By:` line for the model.
- `vite.config.ts` uses `base: './'` so the build works under the Pages sub-path. Don't change it.

## Ground rules (things that break if ignored)

1. **The simulation is deterministic.** Replays, co-op lockstep and saved games all rely on it.
   - Gameplay randomness only from `sim.rng`. Cosmetic randomness (particles) only from `sim.vr`.
     Never use `Math.random()`, `Date` or `performance.now()` inside `src/game/`.
   - **Never mutate simulation state from the UI.** Every player action is a `Command`
     (`src/game/commands.ts`) applied by `Sim.exec()` between ticks, issued through `session.issue()`.
     A new player action = a new `Command` variant + a `case` in `Sim.exec`.
   - Visual/UI-only data the sim produces (events, `waveDamage`) must never be read back by gameplay code.
   - New sim state is saved automatically if it is a typed array or a number/boolean/string field on `Sim`.
     Fields holding **object references** (e.g. a `Tower`) must be mapped to ids in `Sim.snapshot()` and
     back in `Sim.restore()`. `npm run smoke` checks replay + restore equivalence by state hash.
2. **Map size is a live module binding.** `COLS`, `ROWS`, `MAP_W`, `MAP_H` in `src/game/defs.ts` change per
   map (`setMapSize`). Always construct the sim with `Sim.create(config)` (it builds the map before any
   grid-sized arrays exist). Code that builds another map temporarily (menu previews) must restore the size.
3. **`src/game/` is DOM-free** (no `document`, no Pixi). The balance scripts run it in Node.
4. **One texture atlas.** Pixi `ParticleContainer`s need every sprite on a single texture source; the
   atlas is limited to 4096 logical px tall (8192 px at `RES` 2). Models are baked at startup in Web Workers
   (`src/render/bake.ts`, `bake.worker.ts`) — `models.ts`/`bake.ts` must stay DOM-free (OffscreenCanvas only).
   Startup is ~0.56 s; measure it after adding models. Tower bases are shared by all towers (`basel{level}`)
   with each tower's colour drawn as a tinted overlay (`basecorners`) — don't bake per-tower×per-level models.
5. **Two cameras.** Everything is projected through `Projection` (`src/render/projection.ts`): `top`
   (default) and `iso`. Upright things are drawn at `p.x(x,y), p.y(x,y) - z * p.lift`; things lying on the
   ground go in the renderer's ground container (world coordinates through `groundMatrix`). Test both (`V`).
6. **Performance matters to the user.** Sim data is struct-of-arrays typed arrays with no per-frame
   allocation in hot loops; spatial hash for range queries; renderer culls off-screen sprites. The stress
   test button (footer) must stay at 60 fps.

## Architecture

| Path | What it is |
|---|---|
| `src/game/defs.ts` | Static data: enemies, the 34 towers (level-1 stats; levels 2-10 are generated by `grow()`), combos, waves, economy constants |
| `src/game/sim.ts` | The whole simulation: fixed 60 Hz `step()`, enemies/projectiles/fx as typed arrays, towers, zones, drones, hero, items, auras, `exec(cmd)`, `snapshot()/restore()`, `stateHash()`, events |
| `src/game/commands.ts` | The `Command` union |
| `src/game/config.ts` | `GameConfig` (map, difficulty, modifiers, perks, seed), difficulties, challenge modifiers, research perks |
| `src/game/maps.ts`, `mapgen.ts` | Campaign maps, `buildMap()`: cell types `T_BUILD/T_ROCK/T_GATE/T_WATER/T_MOUNT`, rivers, mountain ranges, rocks (obstacles never cut a route), editor paint (RLE); seeded random maps, daily challenge |
| `src/game/partner.ts` | The AI partner (Co-op with AI): reads the sim, returns `Command`s (`place` with `by: PARTNER`); run by `Session` every `PARTNER_EVERY` ticks in local games |
| `src/game/flow.ts`, `spatial.ts`, `rng.ts` | Dijkstra flow fields per route, counting-sort spatial hash, mulberry32 RNG |
| `src/app/session.ts` | A running game: sim + command log; local / replay / co-op lockstep (input delay 6 ticks, state-hash desync checks) |
| `src/app/net.ts` | Co-op over WebRTC via PeerJS (public broker only for the introduction; room codes) |
| `src/app/share.ts` | Replay / custom-map links (deflated JSON in the URL hash) |
| `src/app/storage.ts`, `settings.ts`, `profile.ts` | localStorage/IndexedDB, player settings, medals/perks/leaderboard/custom maps |
| `src/audio/sound.ts` | Playback (panning, distance, convolution reverb, limiter) and the live orchestral score: six pieces played in turn (`TRACKS`), strings/brass/choir over taikos, layered by `intensity`; `nextTrack()`/`prevTrack()` (top bar, `,` `.`), mute and volumes from `settings` (top bar `K`, settings screen) |
| `src/audio/dsp.ts`, `sfx.worker.ts` | Offline synthesis of every effect into sample banks (a few variations each), rendered in a worker ~1.5 s after boot. No audio files |
| `src/render/models.ts` | Every 3D model as stacked top-down parts (sprite stacking) |
| `src/render/bake.ts`, `bake.worker.ts`, `atlas.ts` | Baking models (16 iso headings + 1 top-down frame), effect textures, decals, terrain markings, atlas packing, tower icons |
| `src/render/landscape.ts`, `landscape.worker.ts`, `terrainGL.ts` | Terrain: eroded heightfield + fields, built in a worker; WebGL2 cartoon ground shader |
| `src/render/renderer.ts` | Draws a sim each frame: depth-sorted sprites, projectiles, effects, beams, overlays, wrecks, floating text |
| `src/ui/hud.ts` | DOM HUD: build palette (all towers at once), side info panel, tactical bar, wave preview, reports |
| `src/ui/codex.ts` | The long "how it works" texts for towers, enemies, items, abilities |
| `src/ui/menus.ts`, `editor.ts`, `minimap.ts` | Menu screens, map editor, minimap |
| `src/main.ts` | Boot, camera (pan/zoom/shake), input (mouse, keys, touch), event → sound/effects dispatch, game lifecycle, saves |
| `scripts/` | `smoke.mjs` (browser test), `gauntlet.ts` + `bot.ts` (balance; built with `vite build --ssr`) |
| `public/` | PWA manifest, icon, service worker (offline play; bump `CACHE` when cached files change) |

Data flow per frame: `main.frame()` → `session.advance(dt)` (runs due commands, then `sim.step()` per tick) →
`handleEvents()` (sound, shake, renderer marks) → `view.render(alpha, overlayState)` → `hud.update()`.

## How to…

**Add a tower:** add an entry to `TOWERS` in `defs.ts` (add its `kind` to `TowerKind`) with only its level-1
stats in `levels: [{...}]`; `grow()` generates levels 2-10 (mark `single: true` for a tower with no upgrades).
Implement its behaviour as a `case` in `Sim.updateTower()` (passive/aura towers: in
`refreshAuras()`). Add a turret model `t_<kind>` in `models.ts`, a description in `codex.ts` (`TOWER_HELP`), and a
sound: a recipe in `RECIPES` (`dsp.ts`) named after the kind plus `GAIN`/`THROTTLE` entries in `sound.ts` (the `EV_SHOT` event plays the sound named after the kind). Then run `npm run gauntlet`
and keep its level-1 value per dollar roughly within 0.5–1.1 of the Gun.

**Add an enemy:** `ENEMIES` + an `EN_*` constant in `defs.ts`, a model (`tex` name) in `models.ts`, an entry in
`ENEMY_HELP` (`codex.ts`, same index), a wave rule in `buildWave()`, and optionally a `THREAT_TIPS` line in `hud.ts`.

**Add a player action:** `Command` variant → `Sim.exec` case → UI calls `issue({...})` in `main.ts`.

**AI partner:** `Partner.think(sim)` must stay read-only and cheap. Placement checks (`placeStatus`) run a path
search per route (~1.5 ms each on the biggest map), so a placement is spread over several thinks (`Plan`); keep
every think under ~10 ms. Its commands are logged, so replays never run it. Measure changes with
`SOLO=1 SEEDS=4 npm run bot` (partner alone) and `PARTNER=0.5 npm run bot` (alongside the bot).

**Debug in the browser:** `window.game` exposes `sim`, `session`, `app`, `camera`, `look(x, y, zoom)`,
`quick(mapIndex, difficulty)` (start a game instantly), and the `Session`/`Sim` classes. Headless checks are
easiest with a small `playwright-core` script like `scripts/smoke.mjs`; take screenshots to verify visuals.

## What the user cares about (decisions already made)

- It must be a **mazing** TD (no predefined path) like the original; large maps with pan/zoom and a minimap.
- **Top-down camera is the default**; isometric is an option (`V`), remembered between sessions.
- **All 34 towers visible at once** in the build palette, with icons — no tabs or submenus. The palette is icon
  tiles (icon over price), six columns so each category is one row; the names show under the icons when the
  window is at least 840 px tall (squeezed to fit by `Hud.fitNames()`), and always in the tooltip and the explain
  panel. Info-panel buttons must fit their labels on one line (`npm run smoke` checks).
- Clicking a tower on the battlefield **selects it even while a build tool is active**.
- The side panel **explains** whatever is clicked or hovered (towers, enemies, commander, items, abilities).
- **10 upgrade levels** per tower; every level raises damage, range and fire rate and **looks different**.
- Detailed models, performance, and polish (sound, effects) are all valued. Verify visual changes with screenshots.

**Terrain:** `MapDef.rivers` / `mountains` / `forests` (generated) or `paint` (editor). Water is walkable at
`WATER_SLOW` speed (`Sim.groundSlow`, folded into `tarGrid`) and costs `1 / WATER_SLOW` in the flow fields;
mountains (`T_MOUNT`) and forests (`T_TREE`) are `blocked`. None is buildable (`footprint` needs `T_BUILD`). The look
(all cosmetic, never read by the sim): `render/landscape.ts` builds a heightfield (hills, a ridged spine over every
massif, river valleys) carved by droplet hydraulic erosion, plus moisture, forest mask, cast shadows and AO;
`render/terrainGL.ts` paints it in one WebGL2 shader in a cartoon (Kingdom Rush-like) style; `scenery()` in
`atlas.ts` puts cartoon trees/bushes (`tree*`, `pine*`, `bush*` models) only on blocked cells (forests, mountains),
so they never hide a tower spot. The game starts with a coarse landscape (`buildBackground`, sub=1) and
`refineBackground()` swaps in the detailed one built in `landscape.worker.ts`. Height inputs must be smooth to
their slope (multi-pass blurs, no hard `max`), or the light draws crease lines. Without WebGL2: `flatGround()`. Adding fields to a campaign
`MapDef` changes that map for new games only: saves and replays carry their own copy of the def.

## WW2 mode (branch `ww2`, never merged to `main`: main deploys publicly)

Design and phase plan: `docs/ww2-design.md`; open work: `todo.md` (three fixes, then eight realism features, in order). Four factions (`de`, `su`, `us`, `jp`), each with an arsenal (as the
defender) and an army (as the attacker): `src/game/ww2_<faction>.ts`, wired up in `ww2.ts` (`ARSENALS`, `ARMIES`,
`FACTIONS[f].foes`). Every arsenal fills the standard `SLOTS` in order (`ww2_kit.ts`; other sides `derive()` their
towers from the German ones and change names, models, sounds and stats); every army fills the `ARole` roster that
the shared wave builder `assault()` asks for, scaled by its doctrine. Help texts live with the data.
`GameConfig.ww2 = { side, foe }` selects it; `Sim.create()` calls
`setRuleset()` (`src/game/rules.ts`), which swaps the live bindings `TOWERS`, `ENEMIES`, `COMBOS`, `CATEGORIES`,
`RANKS`, `buildWave` and the `WW2` flag in `defs.ts` (like the map size). Never call it while another game is
running; menus use `rulesetFor(cfg.ww2)` to read a ruleset without installing it.
- Data: `src/game/ww2.ts` (German emplacements, Soviet attackers, waves). A `TowerDef` has a unique `kind` and a
  `role` (the behaviour in `Sim.updateTower`; `Tower.kind` holds the role). WW2 roles beyond the classic ones:
  `at` (armour-piercing direct fire; flak bursts against aircraft), `wire` (slows infantry only), `stuka`.
- Ballistics: `Sim.ballistics()` — `pen` (mm, falls off with range, `penFalloff()`) against `arm` [front, side, rear,
  top] by the shooter's bearing to the hull heading (`penRatio()`); blasts and bombs hit the top. Bounce = ~0
  damage; overmatch may crit. `canHurt()` (same `penRatio()`, from the shooter's position) keeps crews from
  targeting armour they can't penetrate from there; `fireStatus()` tells the panel why a gun holds fire.
  `npm run probe` checks every weapon fires out to the range it shows (`WW2=1 ALL=1` for all matchups). Infantry get suppression (`eSupp`).
- Models: model sets are `scenery` (rocks, trees: every atlas), `classic` (modern), `ww2` (shared) and one per
  faction (`models_ww2.ts` has the kit — soldier, crew, tracks, plane — and the emplacement factories that take a
  faction `Style`, plus the German and Red Army models; `models_su/de/us/jp.ts` the rest). A game's atlas packs only
  `setsFor(cfg.ww2)`; `startGame` rebuilds it when the sets differ. About 1,900 px tall per matchup.
- Balance: `WW2=1 SIDE=us FOE=jp npm run bot` and `WW2=1 SIDE=.. FOE=.. npm run gauntlet` (any matchup).
- Return fire: attackers with an `EnemyDef.gun` pick a defender (`pickDefender`: towers with `hp`, or the
  commander as id -1; `eTgt`), tanks halt to aim (`eAimT`), and `hitDefender()` applies pen against the
  emplacement's `fort` (mm, rises with level like the base visuals). Small arms mostly suppress crews
  (`Tower.supp` slows their fire). At 0 HP a tower becomes rubble (`wreck`: walkable, slow, rebuilt with the
  `repair` command); the Workshop role heals towers in range. Katyusha salvos are typed arrays (`rk*`).
- Units: `UNITS` (live binding, `UnitDef` in defs.ts, German ones in ww2.ts), SoA slots `u*` in `Sim` (stable
  slots, `uUid` in commands). Barracks / motor pool train them (`train`, manpower from HQs and depots), the
  airfield launches Fw 190 patrols (manual). Units path with their own BFS (`unitPathTo`, never touch the flow
  fields), stances Hold/Guard/Hunt/Ambush (`ST_*`), engineers repair and raise rubble, medics heal. Their fire
  goes through `damage()` with the proxy source `unitSrc` (id -2); enemies aim at them as defender id
  -(10 + slot). Commands `unitMove`, `unitStance`.
- Stealth: `TowerDef.camo` (grows with level, `camoOf`). The enemy only shoots what it knows: `towerHidden()`
  is false after firing (`seenT`) or once spotted (`knownT`, set in `updateSpotting()` by any attacker within
  its `spotRange` × (1 − 0.7·camo); recon has a long `EnemyDef.spot`). Hidden guns hit harder; tower mode
  `MODE_AMBUSH` (4) waits for a flank or point-blank shot. Units: `unitHidden()` / `uKnownT`.
- Intelligence: `breach` flow fields (emplacement cells passable at a cost of their max HP and fort; corner
  rule from the real walls; rebuilt when `towerVersion` changes, not saved). Tanks and sappers compare the
  way round with the way through (`thinkBreach`, never on Easy) and shell the wall in front (`eWall`).
  Sappers lift mines and wire; tanks pop smoke under AT fire (`sm*`, blinds both ways); armoured waves open
  with a barrage on known positions (`barrage`, shells in the `rk*` arrays); `adapt()` trades infantry for
  armour by what you built and adds Il-2s if you have no flak.
- Campaign: `src/game/battles.ts` (`BATTLES`; `GameConfig.ww2.battle`). `Sim` reads the battle for `totalWaves`,
  `objectiveId` (its wreck ends the game), preset towers (`setUpBattle`, placed free in the constructor — so
  `restore()` clears the constructor's towers before loading the saved ones), `airLocked()`, money and enemy
  speed; the ruleset applies the battle's roster and doctrine. Maps are painted with the `Painter` in that file
  and get a ground `theme` (terrain shader palette, theatre trees, ruins for rocks). `BATTLE=all npm run bot`.
- Infantry climb dragon's teeth (`slot: 'teeth'`): `foot` flow fields (teeth passable at 1/`TEETH_CLIMB` cost),
  rebuilt with the breach fields at the start of a tick, before enemies move. Vehicles use the normal fields.
- Units dig in (`unitDig`, `uDig` 0→1 over `DIG_TIME`: half damage and suppression for soldiers, front armour only
  for hull-down tanks, hidden while holding fire; a move order climbs out), gain veterancy from kills
  (`unitVet()`, `VET_KILLS`), and engineers lay AT mines (`unitMines`, `uLay`, paid like a placed mine).
- Commander abilities in WW2 are `WW2_ABILITIES` (read them through `heroAbilities()`): Fire Mission (shells as
  `strikes`), Hold the Line (rally + clears suppression), Recon Flight (`eMarkT`: revealed, +20% damage taken).
- The bot attacks the enemy HQ (`offensive()` in bot.ts: Fire Missions, the super-weapon, howitzers within reach).
- AI partner: `Partner.chooseWW2()` picks arsenal slots by the next waves' armour / aircraft / infantry share, and
  rebuilds its own rubble first.
- Bases (all WW2 games): `Sim.setUpBases()` puts our headquarters (the `hq` slot, `Tower.base` = its hp multiplier,
  `bases[route]` = its id; a battle's objective serves instead) near each exit and makes the cells round it the
  route's goal (`route.exit` is rewritten in place, so the flow fields march on it); attackers that get there hold
  and fight, aircraft bomb it and fly home (`overBase`), nothing leaks. `lives` shows its health in %. The enemy's
  base is fixed attackers (`EnemyDef.fixed`: 'hq' | 'mg' | 'at', appended to every army by `garrison()` in ww2.ts)
  at the entries, tracked in the `g*` arrays (slot 0 = their HQ) and excluded from wave-clear checks (`attackers`,
  `garrisonAlive`); lost guns are rebuilt (`GARRISON_REBUILD`, then `eBuild`), positions left alone repair
  themselves, and fortified targets take damage by (pen/armour)² (`ballistics`). Skirmish (`siege`): waves never stop
  and only their HQ's fall wins; a battle can also be won by holding out. New and rebuilt emplacements take
  `buildTime(cost)` to finish (`Tower.buildT`, no firing meanwhile); infantry throw grenades at emplacements next to them.
- Supply: `Tower.ammo` (0..1 of a full stock; a depot's store) drops with every shot (`spend()`, `AMMO_S` s of fire
  by role), an empty gun fires at `EMPTY_RATE`. `updateSupply()` (every `SUPPLY_TICKS`): depots hand ammunition to
  guns in their radius (the depot's `range`) from their store, our headquarters (`HQ_SUPPLY` px) from an endless one,
  crews out of reach scrounge; a depot below `DEPOT_CALL` gets a truck (`UnitDef.truck`, kind `truckKind`, appended
  to every arsenal by `supplyTruck()` in ww2.ts, model `<side>_truck`): `truckWork()` drives it HQ → depot → back
  with `unitPathTo`, the enemy shoots it. The enemy: a supply dump (`fixed: 'depot'`) behind its HQ and a convoy of
  trucks (`EnemyDef.supply`, `updateConvoy()`/`driveConvoy()`, counted in `convoyAlive`, not attackers) that raise
  `foeSupply`; each wave uses `WAVE_SUPPLY`, `waveGroups()` scales the counts by 0.5 + 0.5·foeSupply and a starved
  enemy waits longer for the next wave; the dump's loss burns 0.4.
- Morale: attacking infantry have `eMorale` (1 steady); `updateMorale()` wears it down with heavy losses (hp under 40%)
  and long pins (`ePinT`), a living officer of its wave (`EnemyDef.officer`, ARole `officer`, one per infantry wave,
  `officerAlive[wave & 63]`, wave in `eWave`) steadies it; each death nearby (`lossShock()`) and the officer's fall
  (`OFFICER_SHOCK` to the whole wave) shake it. Below `BREAK`: pinned ones surrender (bounty paid, EV_STATUS 8),
  the others fall back (`eRetreat`, `backField()`: flow fields to the entry, derived, not saved) and leave without
  costing anything; they don't fire. Ours: a lost position or unit (`shakeDefence()`) suppresses crews and soldiers
  nearby and leaves them shaken (`Tower.shakeT`, `uShakeT`: suppression wears off slower); veterans and higher-level
  crews hold better.
- Line of sight and fog: `sightBlock` (forests, mountains, rocks/ruins) blocks sight and fire. Towers keep a mask of
  the cells they see (`losMask()`, derived, per tower id); `findTarget(..., sight)`: 1 the tower's own sight (direct
  fire: `sightTower`), 2 a raycast `clearLine()` (units, commander), 3 seen by anything of ours (`seen()`: mortars,
  rockets, artillery). `updateSight()` (every `SIGHT_TICKS`, and when towers change) builds `seenGrid` (saved): towers'
  sight plus units' and the commander's; attackers that fire stay seen (`eSeenT`), marked ones too; aircraft and the
  enemy's base are always seen. Observers' coverage (`radarGrid`) respects sight. Renderer: a fog wash over unseen
  ground (`updateFog()`, a COLS×ROWS canvas stretched over the map) and faded silhouettes at the last known positions.
  Minimap, picking and the panel ignore unseen attackers.
- Combined arms: rifle and assault squads pair up with a tank of their wave and route (`findLeader()`, `eLead`/
  `eLeadUid`, up to `ESCORTS` each) and keep pace (`escortPace()`: they wait when ahead, hurry when behind). A tank
  with no infantry within `ESCORT_R` (`eEscort`, `checkEscort()` every 15 ticks) takes `CLOSE_BONUS` from infantry
  AT weapons (`closeAssaulter()`) and is close-assaulted (`closeAssault()`: satchels on its deck) by our infantry
  positions (`ASSAULT_SLOTS`, `Tower.nadeCd`) and soldiers (`uNadeCd`); escorted tanks spot 1.5× further. A wave
  lays up to two smoke screens ahead of its tanks when they close on a known strongpoint (fort ≥ 25 or an HQ).
- Counter-battery: every shot of our mortars, rockets and howitzers adds to the enemy's sound-ranging fix on that gun
  (`Tower.fix`, `FIX_SHOTS` shots, less with camouflage, fades with `FIX_FADE`); at 1 their battery (garrison
  `fixed: 'arty'`, from the arsenal's howitzer slot) answers with `CB_SHELLS` shells (the `rk*` arrays) and is seen
  for a while. Their battery is the one base position that is hidden (`seen()`) until found: observers, recon marks
  (which also spot for our artillery) or its own fire.
- Hulks: a knocked-out tank stays (`addHulk()`, the `hk*` arrays, `MAX_HULKS`, `HULK_T` s): its cell is blocked if no
  route or walking attacker depends on it (one path check per tick at most; else it slows like rubble via
  `tarGrid`), it blocks sight and fire (`sightBlock`, saved since it changes; the masks of guns round it are
  dropped), and infantry next to it (`hulkGrid` 2) take `HULK_COVER` damage — ours too. Our engineers clear hulks
  near their post (`pickHulk()`/`doClear()`, task `-(HULK_TASK + cell)`), the enemy's sappers those next to them.
  `hulksChanged()` bumps `towerVersion`. The renderer draws hulks from the sim (no cosmetic wreck for armour).
- Night and weather: `clock` runs with the game time (`DAY_S` per day, from `Battle.hour`, default 8); `night`
  (0..1, dusk 18-20, dawn 5-7) shortens direct fire (`dimMult`) and everyone's sight (`sightMult`, also fog 0.55,
  rain 0.85) and adds camouflage to every position (`camoOf`). Mortars in `MODE_FLARE` fire flares at night
  (`fl*` arrays, `litGrid`): lit cells are seen and in full range (`dimR2` in findTarget). `weather` (`Battle.weather`,
  skirmish from the seed): rain slows vehicles, snow everyone (`weatherSpeed()`), fog grounds air (`airLocked()`,
  air groups dropped in `waveGroups()`). Renderer: `drawSky()` (night wash, flare light, rain/snow, fog haze).
- A moving front: a knocked-out position of their base (MG, AT gun, supply dump, battery — not the HQ) that our
  soldiers hold for `CAPTURE_T` s with no attacker close (`tryCapture()`, `gCap`) becomes ours: a tower of the
  matching slot (`CAPTURE_SLOT`, `Tower.fromG`, placed past their no-build zone with `capturing`), `gOwn`/`gOrig`
  remember it and `gKind` goes to -1, so `enemyGround()` shrinks. After `COUNTER_T` s they counter-attack from their HQ
  (`counterAttack()`, `eHunt`: a flow field to the tower, `huntField()`, derived); if it falls (or is sold) it is
  theirs again (`loseCaptured()`, rebuilt after half the usual time). The minimap draws their ground and its edge,
  the front line (`frontVersion`).
- Music: each faction plays real recordings, public domain on Wikimedia Commons, in `public/music/<faction>/`
  (MP3, loudness-matched). `node scripts/fetch-music.mjs` downloads and converts them and writes
  `public/music/credits.json` (the playlist `sound.ts` reads) and `CREDITS.md`; add a track by adding a line there.
  `sound.setFaction(side)` streams them through an `<audio>` element into the music bus (the service worker leaves
  `/music/` to the network). If they can't load (offline), the synth arrangements in `src/audio/anthems.ts` play.

## Balance notes

The economy and tower values were tuned with `npm run gauntlet` and `npm run bot`. Last bot results: it wins
every map on Easy and the single-route maps on Normal, loses multi-route maps on Normal and most maps on Hard.
The bot only builds along the natural path (no real mazing), so humans do much better. Multi-route maps pay more
(`routeFactor` in `Sim`). Stealth units are revealed by radar or spotted point-blank (`STEALTH_DETECT`).

## Known limitations

- Leaderboard is local to the browser (an online one needs a backend).
- Co-op has no TURN relay: very strict NATs can fail to connect.
- Saves happen at each wave start and when the tab is hidden; continuing resumes from the last save.
